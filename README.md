# When Routing Algorithms Matter: Purification Thresholds and Detour Slack in Quantum Networks

Code, data and paper source for the manuscript of the same title (submitted to *IEEE Transactions on
Quantum Engineering*). Every table, figure and in-text number in the paper and its supplement is
generated by the scripts in this repository from the stored results, and re-running the simulations
reproduces those results bit for bit.

## The question

Entanglement routing algorithms are usually compared under one set of physical parameters. This work
asks a prior question: **when can the choice of path change whether a request meets its fidelity
target at all?**

Purification, swapping and memory decay are monotone in link quality. So, as long as noise never
improves a link and storage times are fixed by the path, a path can succeed only if it would pass
with every link in its best state; we call such a path *viable*.

- With **no** viable path, every single-path routing policy fails.
- With **one**, a fixed route is optimal.
- Only with **two or more** can routing help.

On corner-to-corner grid requests this reduces to a closed-form **detour slack** *s*, the number of
extra hops a clean detour can afford (Corollary 1).

## Results at a glance

| Result | Number |
|---|---|
| Closed-form slack vs. simulation | agree in all 345 grid configurations (consistency check: same physics) |
| Each BBPSSW round (F_th = 0.8) | extends the routing-sensitive regime by about one grid size; one to two at lower thresholds |
| Charging raw-pair generation time | gives a finite optimal number of rounds and a design chart for the required coherence time |
| Discrete-event, density-matrix check (SeQUeNCe kernel) | reproduces every regime call, and every routing outcome on the headline configuration, under the model's assumptions; with each memory's storage time resolved, routing needs 1.8–3.4× the closed-form coherence time, between the optimistic and pessimistic accountings in every case (24 of 24); calls with small upper margins shift; near the boundary the calls are soft (sweep across the boundary in block S3) |
| DEJMPS (closed form, certified by explicit paths) | routing-sensitive with 2 rounds on every grid 4×4–8×8, where BBPSSW needs 3–6; slack saturates from 3 rounds |
| Causal exact objective (no swap foreknowledge) | succeeds on exactly the oracle's trials in all 45,000 routing-sensitive trials of Table III |
| Headline cell (5×5, r = 3, n = 5000) | shortest path 73.16 %, PG (local) 96.62 %, exact oracle 98.24 % |
| Dijkstra on −log F | matched the exact oracle in every simulated configuration with unusable noisy links (not guaranteed: a counterexample is given) |

In total: 1,227,000 paired Monte Carlo trials in 912 configurations, plus the discrete-event runs.

## Reproduce the paper from the stored results (about 2 minutes)

```bash
conda env create -f environment.yml && conda activate qrouting
python reproduce.py --pdf --tests
```

`reproduce.py` runs every closed-form and table/figure script, re-checks the paper's numbers against
the raw trials (`check_numbers.py`), re-analyses the stored discrete-event run (`analyze.py`, which
must report `0 FAIL`), copies the generated tables and macros into `paper/`, and, with `--pdf`,
compiles `paper/main.pdf` and `paper/supplement.pdf` and fails on any LaTeX error, overfull box or
undefined reference. It works on Linux, macOS and Windows.

## Re-run the simulations

```bash
python code/run_study_tqe.py                 # Monte Carlo blocks E1–E13 (about 15 min on 2 cores)

cd des_validation                            # discrete-event run: own environment (Python >= 3.12)
conda env create -f environment.yml && conda activate qrf-des
python smoke_test.py && python test_des_physics.py
python run_des.py                            # PF, PR, T, S1, S2
python run_des.py --only TD,T6a,T6b,T7a,T7b  # further blocks
python analyze.py && python paper_extra.py
```

Both runs are seeded; the Monte Carlo run reproduces `results_tqe/` bit for bit. See
`des_validation/README.md` for the run times and for what the discrete-event simulation shares with
the scalar model.
